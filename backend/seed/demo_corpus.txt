Continuous water quality monitoring with low-power IoT sensor nodes

Traditional water quality assessment relies on manual sampling, where a technician collects bottles from a river, lake or distribution network and carries them to a laboratory. The process is slow, expensive and only captures isolated snapshots of a system that changes by the hour. A network of inexpensive sensor nodes can replace most of these visits by measuring key parameters continuously and reporting them wherever a signal is available.

A typical node combines a microcontroller with probes for pH, turbidity, dissolved oxygen, electrical conductivity and temperature. The probes produce small analogue voltages, so each channel passes through an amplifier and a 16-bit analog to digital converter before the firmware reads it. Calibration against standard buffer solutions is stored in non-volatile memory, and a temperature reading is used to compensate the pH and conductivity values. The firmware spends most of its time in deep sleep, wakes every ten minutes, powers the probes, waits for them to settle, takes the median of several samples and returns to sleep. With a small lithium cell and a solar panel such a node can run for many months without maintenance.

Readings travel to a gateway using LoRa radio, which trades bandwidth for range and penetrates vegetation and riverbank terrain far better than Wi-Fi. The gateway forwards each packet over a cellular link to a broker using the MQTT publish and subscribe protocol. Topics follow a simple hierarchy of site, node and parameter, which makes it easy for several consumers to subscribe to exactly the data they need. Messages carry a timestamp, a node identifier, the raw value and a quality flag so that downstream code can tell the difference between a failed probe and a genuine anomaly.

On the server side a Python service subscribes to the broker, validates every message and writes it to a time series table in a relational database. A rolling window of recent values is kept in memory to detect sudden jumps, drifting sensors and flat lines that suggest a disconnected probe. Simple statistical rules, such as a z-score threshold against the previous twenty-four hours, catch most faults without any machine learning, and the flagged readings are excluded from averages until a person reviews them.

The dashboard presents the latest value for every site on a map, with colour coding that follows national drinking water guidelines. Selecting a site opens trend charts for each parameter and a log of alerts. Operators can subscribe to email or messaging notifications when turbidity rises above a limit for more than thirty minutes, which usually indicates a storm event or a broken main upstream.

Several practical lessons emerge from field deployments. Biofouling slowly coats optical and electrochemical probes, so scheduled cleaning and drift checks matter more than raw accuracy. Enclosures must tolerate condensation and direct sun. Timestamps should be recorded in UTC at the node to avoid confusion when the gateway loses connectivity and later uploads buffered data. Finally, an open data format lets universities, local authorities and community groups reuse the measurements for their own research.
